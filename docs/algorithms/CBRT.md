# Cube-root integer algorithm

For a nonzero finite binary value, normalize its magnitude as `M * 2^(E-p)`,
where M has p+1 significant bits (p=23 or 52). Write E=3K+r with 0<=r<3.
The target root significand is the cube root of the integer
`N = M * 2^(2p+r)`.

The significand lies in [2^p,2^(p+1)). Integer bisection finds L such that
`L^3 <= N < (L+1)^3`. Products use six 32-bit limbs. Even the midpoint test
`(2L+1)^3` needs at most 162 bits, within the 192-bit capacity. Each multiplication
accumulator consists of one 32x32 product, one 32-bit output digit and one
32-bit carry, whose sum fits unsigned 64 bits.

If L^3=N, the result is exact and no inexact exception is raised. Otherwise:
- nearest-even compares `(2L+1)^3` with `8N`;
- toward zero keeps L;
- upward/downward choose L or L+1 according to the original sign.

The chosen significand is normalized if incrementing crossed the upper boundary,
then stored with exponent K and the input sign. All nonzero finite input cube
roots fit the normal exponent range for binary32/binary64, so no final overflow
or underflow is needed. Zero and infinity preserve their sign; NaNs preserve
payload/sign and signaling NaNs are quieted with FE_INVALID.

`make-cbrt-reference.ps1` is a test-only independent implementation using unbounded
BigInteger Newton iteration and an exact midpoint comparison. It generates C
fixture text, never compiler binaries. The retained fixtures cover 320 inputs;
the client checks all four rounding modes, binary32 plus binary64/Windows long
double results, and inexact flags. The tests are not an exhaustive enumeration
of all possible input encodings. Production generation remains entirely within
the custom compiler/linker chain.

# 误差函数的实现与验证

下文源码与测试路径均相对于 `src/bootstrap-c99/complex/`。提及的测试日志由对应套件生成，不是必需的源码输入。

运行库提供 float、double 和 Windows binary64 long double 的 erf/erfc。对于 |x|<2，使用双分量 double 运算累加 erf 定义泰勒级数的 100 项。对于正数 x>=2，直接采用 NIST DLMF 7.9.2 的连分式，以 400 步反向递推计算 erfc，再乘以 exp(-x*x)/sqrt(pi)。指数运算和目标格式打包内核是本项目运行库实现的私有源码副本。平方、连分式和指数约化保留残差位，指数缩放只在最终目标格式打包时应用，避免用一减去已舍入的 erf 来计算微小余量。

算法依据：[NIST DLMF 7.9.E2](https://dlmf.nist.gov/7.9.E2)。C99 接口约定见 [N1256](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1256.pdf) 第 7.12.8.1/2 节及附录 F。

有限正数 erf 输入 >=6，以及负数 erfc 输入 <=-6，使用极限值及正确的定向相邻值，并设置不精确标志。正数 erfc 输入 >=28 时，依据舍入模式返回零或最小次正规值，并设置 ERANGE、下溢和不精确标志。这些分界对两种格式均为保守选择。极小 erf 输入先规范化，再乘以 2/sqrt(pi)；极小 erfc 输入使用一的适当相邻值。带符号零和无穷返回精确结果。NaN 载荷保留；信号 NaN 转为安静 NaN 并触发无效操作异常。内部计算使用最近舍入并暂存异常环境，在目标格式打包前恢复调用者的环境。

make-erf-reference.ps1 只生成 C 测试源码。参考实现用 Machin 公式和整数 atan 级数构造 pi，用整数牛顿迭代求 sqrt(pi)，再以定点 BigInteger 运算求定义泰勒级数。800 位十进制精度足以处理到 x=28 的 erfc 尾部抵消；其算法与运行库尾部采用的连分式不同。ERF-ORACLE.txt 记录以 900 位精度独立比较参考数据的结果。

ERF.txt 在四种舍入模式下检查 1,176 条操作/输入/精度记录；binary64 记录还通过 long double 调用。每个结果均逐位比较，覆盖分段边界邻近值、次正规输入及 erfc 输出、正负输入。额外检查异常标志、errno、信号 NaN、无穷、带符号零及已有错误状态的保留。三次链接执行使用两代自制编译器及混合代次的提供方/调用方，要求相应目标文件和可执行文件逐字节一致。

这些是选定输入的结果，不是全输入空间正确舍入的证明。不宣称统一的连分式截断/舍入误差上界，也不宣称穷尽所有难舍入输入。

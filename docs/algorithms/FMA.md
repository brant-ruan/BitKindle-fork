# Fused multiply-add implementation

fma.c implements binary32 and binary64 (also Windows long double) using integer
arithmetic. It does not require an FMA instruction or change the rounding mode.

Finite inputs are decoded as signed integer significands times powers of two.
The exact product uses four base-2^32 limbs. Product and addend are placed on a
common lattice with quantum 2^-298 for binary32 or 2^-2148 for binary64. Signed
addition/subtraction occurs before any bits are discarded. The largest possible
product bit index is 553 or 4195 respectively; 20 or 136 active limbs provide
640 or 4352 bits, including carry headroom. Multiplication accumulator bounds
are at most (2^32-1)^2+2*(2^32-1)=2^64-1.

The final result retains the destination precision, or the subnormal quantum,
then uses guard/sticky bits for nearest-even or directed rounding. Overflow is
classified after rounding with an unbounded exponent. Underflow uses tininess
after rounding and requires inexactness. Exact cancellation is negative zero
only in downward rounding; same-sign input zeros preserve their sign.

Nonfinite handling quiets signaling NaNs and raises invalid, preserves the first
NaN payload, rejects zero times infinity and opposing infinite terms, and
otherwise propagates infinity. This implementation chooses invalid for zero
 times infinity even with a quiet-NaN addend. Domain errors use EDOM; overflow
and inexact tiny results use ERANGE. Existing flags and errno remain untouched
when the operation does not require a new error.

make-fma-reference.ps1 generates C test source only. Its independent signed
BigInteger sum and DivRem rounding provide 480 triples in all four modes,
including subnormal inputs and extreme exponent differences. It does not create
or modify binary compiler artifacts. Both custom compiler generations compile
and link the fixtures. Dedicated tests add exact product cancellation, overflow
cancellation, ties across the subnormal/normal boundary, signed zeros, NaNs,
infinities, and preservation of prior exception flags and errno.

Algorithm tests complement the release build and audit; they do not establish full C89/C99 conformance.

# Error function implementation and validation

The library supplies erf/erfc in float, double and Windows binary64 long double.
For |x|<2 the implementation sums 100 terms of the defining erf Taylor series
using two-component double arithmetic. For positive x>=2, erfc is computed
directly from the continued fraction in NIST DLMF 7.9.2, with 400 backward steps,
then multiplied by exp(-x*x)/sqrt(pi). The exponential and target packing kernels
are private source copies of this project's runtime implementation.
The square, continued fraction and exponential reduction retain residual bits;
the exponential scale is applied only during final target packing. Thus a small
complement is not computed by subtracting a rounded erf value from one.

Source: https://dlmf.nist.gov/7.9.E2
C99 contract: https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1256.pdf
(section 7.12.8.1/2 and Annex F).

Finite positive erf arguments >=6 and negative erfc arguments <=-6 use limiting
values with the correct directed neighbor and inexact flag. Positive erfc
arguments >=28 use zero or minimum subnormal according to rounding mode, with
ERANGE and underflow/inexact. These cutoffs are conservative for both formats.
Extremely small erf inputs are normalized before multiplication by 2/sqrt(pi),
and tiny erfc inputs use the appropriate neighbor of one. Signed zeros and
infinities return exact results. NaN payloads are preserved; signaling NaNs are
quieted with invalid. The internal computation runs in nearest mode with held
exceptions, then restores the caller environment before target packing.

make-erf-reference.ps1 writes only C test source. The oracle constructs pi using
Machin's formula and integer atan series, finds sqrt(pi) using integer Newton
iteration, and evaluates the defining Taylor series in fixed-point BigInteger
arithmetic. Its 800 decimal places allow cancellation in the erfc tail through
x=28; the reference algorithm differs from the library's tail continued fraction.
ERF-ORACLE.txt records an independent 900-place reference-data comparison.

ERF.txt checks 1,176 operation/input/precision records under all four rounding
modes. Binary64 records are also called as long double. Every result is compared
bit for bit, including neighboring values at the piecewise cutoffs, subnormal
inputs and erfc outputs, and signed inputs. Additional checks cover exception
flags, errno, signaling NaNs, infinities, signed zero and preservation of existing
error state. The three linked runs use both custom compiler generations and a
mixed-generation provider/client; the tests require matching object and executable bytes.

These are selected-input results, not a proof of correct rounding over the full
input space. No uniform continued-fraction truncation/roundoff bound or exhaustive
coverage of hard-to-round inputs is claimed.

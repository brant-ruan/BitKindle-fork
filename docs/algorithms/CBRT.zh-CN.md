# 立方根的整数算法

下文源码与测试路径均相对于 `src/bootstrap-c99/complex/`。提及的测试日志由对应套件生成，不是必需的源码输入。

将非零有限二进制数的绝对值规范化为 `M * 2^(E-p)`，其中 M 有 p+1 个有效位（p=23 或 52）。令 E=3K+r，满足 0<=r<3。目标立方根的有效数是整数 `N = M * 2^(2p+r)` 的立方根。

有效数位于 [2^p,2^(p+1))。整数二分查找得到满足 `L^3 <= N < (L+1)^3` 的 L。乘积使用六个 32 位分段表示；即使中点检查中的 `(2L+1)^3` 也最多需要 162 位，不超过 192 位容量。每次乘法累加由一个 32×32 位乘积、一个 32 位输出分段和一个 32 位进位组成，其和可由无符号 64 位整数容纳。

若 L^3=N，结果精确，不触发不精确异常。否则：

- 最近偶数舍入比较 `(2L+1)^3` 与 `8N`。
- 向零舍入保留 L。
- 向上或向下舍入依据输入符号选择 L 或 L+1。

若递增后越过上界，则将选定的有效数重新规范化，再以指数 K 和输入符号保存。所有非零有限输入的立方根都落在 binary32/binary64 的正规指数范围内，无须处理最终结果的溢出或下溢。零和无穷保留符号；NaN 保留载荷和符号，信号 NaN 转为安静 NaN 并触发 FE_INVALID。

`make-cbrt-reference.ps1` 是仅用于测试的独立实现，使用任意精度 BigInteger 牛顿迭代和精确中点比较。它只生成 C 测试数据文本，不生成编译器二进制。保留的测试数据覆盖 320 个输入；测试程序检查四种舍入模式、binary32 和 binary64/Windows long double 结果，以及不精确异常标志。测试并未穷举全部输入编码。正式二进制产物始终由自制编译器和链接器生成。

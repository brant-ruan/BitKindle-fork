# C1O1 目标文件格式

`.c1o` 是本工具链用于分开编译和链接的私有目标文件格式，当前格式标识为 `C1O1`，目标机器为 Windows x64。它不是 COFF `.obj`、PE 可执行文件或导入库。

本页描述当前实现。格式读取与校验以 [linker/object.c](../src/bootstrap-c99/linker/object.c) 为依据；最终编译器的写出实现见 [host/object-output.c](../src/bootstrap-c99/host/object-output.c)。文件通过显式字节读写序列化，不是把 C 结构体内存直接写入文件，也没有统一的格式头文件。

## 编码与整体布局

所有多字节整数采用小端序。下文 `u32`、`u64` 分别表示无符号 32、64 位整数，`i64` 表示二进制补码有符号 64 位整数。所有索引从零开始；表内字段偏移以该条记录起点为基准。

文件依次排列如下，区域之间没有隐含填充：

```text
32 字节文件头
节表：section_count × 48 字节
符号表：symbol_count × 40 字节
重定位表：fixup_count × 32 字节
名称区：name_size 字节
数据区：payload_size 字节
```

因此，各区域的文件偏移为：

```text
section_offset = 32
symbol_offset  = section_offset + section_count * 48
fixup_offset   = symbol_offset  + symbol_count * 40
name_offset    = fixup_offset   + fixup_count * 32
payload_offset = name_offset   + name_size
file_size      = payload_offset + payload_size
```

实际文件长度必须恰好等于上述 `file_size`，不能截断或附加尾部数据。

## 文件头：32 字节

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | 4 字节 | ASCII `C1O1`，即 `43 31 4F 31` |
| 4 | u32 | 机器类型，必须为 `0x8664` |
| 8 | u32 | `section_count`：节记录数 |
| 12 | u32 | `symbol_count`：符号记录数 |
| 16 | u32 | `fixup_count`：重定位记录数 |
| 20 | u32 | `name_size`：名称区字节数 |
| 24 | u32 | `payload_size`：数据区字节数 |
| 28 | u32 | 保留，必须为零 |

## 节记录：48 字节

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | u64 | 内存大小 `memory_size` |
| 8 | u64 | 文件数据大小 `file_size` |
| 16 | u64 | 内存对齐要求 `alignment` |
| 24 | u64 | 输出布局的文件对齐要求 `file_alignment` |
| 32 | u64 | 本节数据相对于数据区起点的偏移 |
| 40 | u32 | 属性位：读 = 1，写 = 2，执行 = 4 |
| 44 | u32 | 保留，必须为零 |

约束如下：

- `file_size <= memory_size`，两项对齐值均须为非零的 2 的幂。
- 属性值为 1～7，例如读写为 3，读执行为 5。
- 有文件数据的节按节表顺序紧密占用数据区，不允许空洞、重叠或未被节使用的尾部数据。
- `file_size == 0` 时，数据偏移必须为零。此类节只占内存，例如 BSS；内存大小超过文件数据大小的部分按零填充处理。

节记录没有节名。这里的文件对齐要求不表示 `.c1o` 内部的数据区需要插入对齐填充。

## 符号记录：40 字节

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | u32 | 名称相对于名称区起点的偏移 |
| 4 | u32 | 绑定类型，见下表 |
| 8 | u32 | 所属节索引；无所属节时为 `0xFFFFFFFF` |
| 12 | u32 | 保留，必须为零 |
| 16 | u64 | 符号相对于所属节起点的偏移 `value` |
| 24 | u64 | 符号大小 `size` |
| 32 | u64 | 对齐要求 `alignment` |

| 值 | 名称 | 语义 |
| --- | --- | --- |
| 0 | `LK_UNDEFINED` | 未定义引用，等待链接时解析 |
| 1 | `LK_LOCAL` | 当前输入模块内的局部定义 |
| 2 | `LK_GLOBAL` | 可供其他模块引用的全局定义 |
| 3 | `LK_COMMON` | 由链接器分配的公共零初始化存储 |

名称是以 NUL 结束的非空字节串，长度为 1～255 字节，不含结束符。名称按符号表顺序紧密排列；即使同名，也各自保存一份。名称区不得有未使用的尾部字节。读取器按字节处理名称，不负责 Unicode 编码转换。

所有符号的对齐值都必须是非零的 2 的幂。局部和全局定义的节索引必须有效，`value` 与 `size` 必须落在该节内存范围内；未定义和 COMMON 符号的节索引必须为 `0xFFFFFFFF`，`value` 必须为零。

链接时，重复的全局定义报错；全局定义优先于同名 COMMON。同名 COMMON 按最大大小、最大对齐要求合并。未定义符号可以暂时未解析，但实际需要其地址时必须能够解析。相关实现见 [symbols.c](../src/bootstrap-c99/linker/symbols.c)。

## 重定位记录：32 字节

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | u32 | 待修补位置所在的节索引 |
| 4 | u32 | 目标符号索引 |
| 8 | u32 | 重定位类型 |
| 12 | u32 | 保留，必须为零 |
| 16 | u64 | 修补字段相对于所在节起点的偏移 |
| 24 | i64 | 显式加数 `A` |

设 `S` 为解析后的目标符号虚拟地址，`P` 为修补字段第一个字节的虚拟地址，`B` 为映像基址。链接器按下表计算，并以小端序覆盖修补字段；原字段内容不作为隐式加数。

| 值 | 类型 | 字节数 | 写入值 |
| --- | --- | --- | --- |
| 1 | `LK_ABS64` | 8 | `S + A`，须在无符号 64 位范围内 |
| 2 | `LK_ABS32` | 4 | `S + A`，须在无符号 32 位范围内 |
| 3 | `LK_REL32` | 4 | `S + A - (P + 4)`，须在有符号 32 位范围内 |
| 4 | `LK_RVA32` | 4 | `S + A - B`，须在无符号 32 位范围内 |

所有类型都会先检查 `S + A` 的无符号 64 位溢出或下溢。节索引和符号索引必须有效；整个修补字段必须位于节的文件数据范围内，不能只落在零填充区。同一节中的修补字段不得相互重叠，该约束在应用重定位时检查。

例如 `LK_REL32` 中，`S=0x401100`、`P=0x401020`、`A=0`，写入值为 `0xDC`，对应字节 `DC 00 00 00`。

类型和计算见 [relocate.c](../src/bootstrap-c99/linker/relocate.c)，批量检查和写入见 [fixups.c](../src/bootstrap-c99/linker/fixups.c)。

## 当前编译器的输出约定

上述格式可表达多个节及四种重定位；最终编译器当前写出的是其中一个子集：

- 两个节：索引 0 为读执行的代码／字面量数据，索引 1 为读写的零填充存储。两节的内存对齐为 16，文件对齐为 1。
- 前两个符号是局部符号 `$code`、`$bss`，分别指向这两个节的起点。
- 函数调用、对象引用和地址引用使用 `LK_REL32`。
- 需要初始化代码时，额外生成局部符号 `$init`。链接器识别该名称，在进入程序入口之前调用对应初始化代码。这是编译器与链接器的启动约定，不是文件头字段。

DLL 导入配置、最终入口名称、控制台／GUI 子系统由链接器命令行提供，不保存在 `.c1o` 文件头中。使用方法见 [USAGE.zh-CN.md](../USAGE.zh-CN.md)。

## 实现容量与校验边界

当前读取器对每个对象施加以下上限；这些是实现容量，不是字段位宽的上限：

| 项目 | 上限 |
| --- | ---: |
| 节 | 1,024 |
| 符号 | 4,096 |
| 重定位 | 16,384 |
| 名称区 | 1 MiB |
| 数据区 | 16 MiB |

链接器合并后的节、符号和重定位也受相应固定容量限制，并非每个输入都能同时用满这些容量。最终编译器另将单个目标文件总输出限制为 1,049,088 字节，因此读取器允许的范围大于当前编译器能够写出的范围。

文件结构校验通过不代表链接必然成功：链接阶段还会检查符号冲突、未解析引用、修补字段重叠、地址与相对位移溢出，以及 PE 布局约束。

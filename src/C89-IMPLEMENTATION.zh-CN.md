# C89/C99 实现约定

本文说明 Windows x64 版本的语言行为、库约定及支持边界。当前源码见 bootstrap-c99/SOURCES.json；使用方法见 [USAGE.zh-CN.md](../USAGE.zh-CN.md)，构建与测试命令见 [逐阶段教程](../WALKTHROUGH.zh-CN.md)。

文档覆盖范围参考 [C89 草案 A.6.3](https://port70.net/~nsz/c/c89/c89-draft.html#A.6.3)。该附录要求记录实现定义行为；通过自编译或局部测试不能替代这些约定及其核验。

## 数据模型

| 类型或性质 | 实现选择 | 证据 |
| --- | --- | --- |
| 字节 | 8 位 | `include/limits.h`，facts 探针 |
| char / signed char | 1 字节，-128 至 127 | limits 头文件，facts / integers 探针 |
| unsigned char | 1 字节，0 至 255 | 同上 |
| short / unsigned short | 2 字节，分别为 -32768 至 32767、0 至 65535 | 同上 |
| int / long | 均为 4 字节，-2147483648 至 2147483647 | 同上 |
| unsigned int / unsigned long | 均为 4 字节，0 至 4294967295 | 同上 |
| 指针 | 8 字节 | facts 探针 |
| size_t / ptrdiff_t | 分别为 unsigned long long / long long，8 字节 | `base/include/stddef.h`，facts 探针 |
| wchar_t | unsigned short，2 字节 | 同上，字符探针 |
| NULL | `((void *)0)` | `base/include/stddef.h` |
| 整数字节序 | 小端 | facts 探针 |
| float | 4 字节，二进制有效位 24 | float 头文件，facts 探针 |
| double / long double | 均为 8 字节，二进制有效位 53 | 同上 |

long long 是本实现支持的扩展类型，也用于定义 64 位的 size_t 和 ptrdiff_t。显式 C89 模式对 long long 语法发出扩展警告；本表不声称 C89 本身规定了这个类型。

## 整数运算与转换

运行时整数窄化保留目标宽度的低位，随后按目标类型作符号扩展或零扩展。有符号结果按二进制补码解释。例如 `(signed char)255`、`(short)65535`、`(int)4294967295U` 均为 -1。有符号右移使用算术右移。负数除法示例为 `-7/3 == -2`、`-7%3 == -1`。

有符号整数的 `&`、`|`、`^` 和 `~` 按二进制补码逐位运算，不采用符号数值分离的表示。二元运算先完成整数提升及通常算术转换，`~` 对提升后的类型取反；结果按所得整数类型的宽度解释。当前 `host/compiler.c` 的二元生成路径使用 AND/OR/XOR，单目路径使用 NOT，常量求值采用相同位运算；负数除法向零截断，余数非零时与被除数同号。

本实现将 C89 有符号左移规定为：对提升后类型的补码位模式左移、舍弃高位、低位补零，并按该类型解释结果；移位计数必须非负且小于类型位宽。例如 `-1<<1` 得到 -2，`1<<31` 得到 32 位最小负数。运行时和三条常量求值路径使用相同规则；C99 保留其非负操作数与结果可表示性限制。选择依据为 [WG14 C90 DR 081](https://www.open-std.org/jtc1/sc22/wg14/issues/c90/issue0081.html)。

源码证据为 `host/compiler.c` 的 `convert`、`cast_to` 和整数运算生成路径。补充包 integers 测试在直接输出可执行文件和分别编译链接两条路径中，对每代编译器检查 69,634 个输入及六个静态初始化器。该覆盖支持所列实现选择，尚不构成对所有常量折叠组合的穷尽证明。

## 浮点转换

`floating_convert` 用 SSE 转换指令完成运行时整数与浮点转换以及 double/float 精度转换。默认环境下，整数到浮点和浮点窄化采用最接近值，中点取偶数；可表示范围内的浮点转整数截去小数部分，方向趋零。double 与 long double 使用相同表示，无额外精度转换。运行时舍入受 MXCSR 控制，公开 FLT_ROUNDS 宏每次读取该控制状态；该宏不是固定整数常量。

转换测试覆盖默认环境下的中点、正负值、小数截断和若干静态/运行时一致性场景；这些有限用例不证明全部舍入模式、异常和数值边界。

## 数学库错误返回

下面列出数学函数的错误返回约定；测试每组调用前将 errno 清零，以区分新错误和既有状态。

| 所测调用 | 返回值 | errno |
| --- | --- | --- |
| acos(2)、asin(-2)、sqrt(-1)、log(-1)、log10(-1) | NaN | EDOM |
| pow(-2,0.5)、fmod(1,0) | NaN | EDOM |
| log(0)、log10(0) | -HUGE_VAL | ERANGE |
| pow(0,-1)、exp(1000) | HUGE_VAL | ERANGE |
| exp(-1000)、ldexp(DBL_MIN,-1000) | 零 | ERANGE |
| ldexp(DBL_MIN,-1) | 精确的正次正规值 | 保持为零 |
| pow(0,0) | 1 | 保持为零 |
| atan2(0,0) | 零 | 保持为零 |

源码中 `math-scale.c` 在舍入后结果微小且不精确时设置 ERANGE，精确缩放得到的次正规值不因此设置 errno；不能把所有次正规结果统称为已报告下溢。其他函数分别由 math-asin、math-sqrt、math-log、math-pow、math-remainder、math-exp 和 math-atan2 模块处理。上表是经过实际执行的具体约定，不是对所有参数、所有舍入模式或全库精度上界的证明；不提供全库统一最坏误差上界。

## 指针与整数转换

根据 `host/compiler.c` 的 `cast_to` 和 `convert`，本实现将指针按 64 位地址表示。显式整数到指针转换中，32 位及更窄的有符号值按提升后类型作符号扩展，无符号 32 位值零扩展；64 位整数的位模式保持不变。指针转整数按目标宽度取低位，并按目标整数类型解释。零地址是空指针表示。

构造的指针值只能在满足目标对象或函数的实际要求时解引用或调用；整数与指针往返的实现约定不意味着任意整数都是可访问地址，也不保证可移植到其他 C 实现。

## 字符和字符串

基本字符使用 ASCII 对应值。标准控制转义映射为：`\a=7`、`\b=8`、`\f=12`、`\n=10`、`\r=13`、`\t=9`、`\v=11`；反斜线、单引号、双引号和问号的转义保留对应字符值。八进制转义最多读三位，十六进制转义读取后续十六进制数字。窄转义范围为 0..255，宽转义范围为 0..65535；越界或未知转义会诊断并拒绝。

窄字符常量具有 int 类型。本实现 plain char 有符号，值 128..255 的单字符常量得到 -128..-1，例如 `'\xff' == -1`。窄多字符常量从左至右按字节拼接，保留低 32 位，例如 `'AB' == 0x4142`、`'ABCDE' == 0x42434445`。宽字符常量具有 wchar_t 类型，多字符时保留最后一个单元，例如 `L'AB' == 66`。

字符及字符串的实现入口为 `escape`、`character` 和 `string_token`。

原始源码字节 128..255 独立映射为同值字符单元；窄字符常量的 int 值另按前述符号规则解释。L 前缀不会启用 UTF-8 解码。源文件采用单字节映射；这不承诺通用 Unicode 源码支持，也不等同于头文件路径的编码规则。

C locale 的多字节转换采用无移位状态的单字节映射：0..255 对应同值宽字符，宽字符超过 255 时不能转换回单字节。补充包 multibyte 测试覆盖所有 256 个字节，以及终止符、截断、零长度和无效宽值边界。这是本实现的 locale 选择。

## register 与 volatile

register 不要求把对象长期保存在机器寄存器中。本实现仍为 register 局部变量和参数分配栈位置，并记录 register 属性以诊断取地址等不允许的操作；它不是单独的寄存器优化模式。源码依据为参数绑定、`declaration`、`load` 及地址运算路径。

标量值访问由 `load_opcode`、`load`、`indirect_value` 和 `store` 发出对应宽度的内存读写。volatile 不提供额外原子性或线程同步保证。含 volatile 的记录在其整个值被消费时，通过 `record_read` 实体化到临时对象；成员选择、地址形成和赋值目标不因此先复制整个记录。记录复制由 `store_record` 按字节复制其完整大小，包括布局中的填充区。volatile 聚合初始化先准备临时内容，再复制到目标。

C89 member-volatile、register-volatile、volatile-list、volatile-list-copy、volatile-list-helper 及相关拒绝案例覆盖上述生成路径，不覆盖所有设备内存、副作用计数或并发场景。

## 结构、联合、枚举与位字段

根据 `type_align` 和 `record_specifier`，标量成员按其大小对齐；数组采用元素对齐，嵌套记录采用该记录的对齐。普通结构成员向上对齐后顺序排列，结构总大小向上补齐到最大成员对齐。联合成员都从偏移零开始，大小为最大成员大小再按最大对齐补齐。

int 位字段以 4 字节单元分配，低位在先。连续字段在同一单元有足够剩余位时合并，否则从下一个对齐单元开始，不跨越单元边界。普通成员会结束当前位字段单元；零宽字段也终止合并。普通 int 位字段按有符号值读取。枚举占 4 字节，枚举值范围为 int 的范围。

联合不同成员读取复用底层表示，例如写入 `0x41424344` 后读取 char 成员得到 `0x44`；此例不保证任意类型组合都有可用值，有限布局测试也不覆盖所有组合。

## 包含文件与 pragma

`#if` / `#elif` 的算术使用 64 位有符号或无符号整数，独立于执行环境中 32 位的 `long`。例如 `0xffffffffU + 1` 在条件包含中不回绕到零，`0xffffffffffffffffUL + 1` 则按模 2^64 回绕。无后缀十六进制常量 `0xffffffff` 在这里为正的有符号值。C89 允许这两个环境的整数位宽不同，见 [WG14 Rationale N937 第 5 节](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n937.pdf)。C99 的条件包含使用对应于本实现 `intmax_t` / `uintmax_t` 的 64 位域。对应测试见 `language-regression-tests/`。

根据 `pp_search_header`：绝对路径直接尝试打开；引号包含依次尝试当前被包含文件的目录、进程工作目录，再进入公共搜索路径。公共搜索路径按 `C1_INCLUDE` 中分号分隔的非空目录依次搜索，最后尝试工作目录下的 `include`。尖括号包含直接进入公共搜索路径。文件路径交给 Win32 `CreateFileA`；本文暂不额外承诺非 ASCII 文件名的编码兼容范围。

根据 `pp_pragma_apply`：非 STDC pragma 被忽略；STDC 的 FP_CONTRACT、FENV_ACCESS、CX_LIMITED_RANGE 接受 ON、OFF、DEFAULT 形式。FP_CONTRACT 的实现策略为从不收缩表达式，默认状态约定为 OFF；ON 允许但不强制收缩，因此仍逐个执行运算。FENV_ACCESS 的实现默认状态约定为 OFF，DEFAULT 表示 OFF。当前后端对所有状态都保守保留按序执行、受运行时浮点环境影响的运算，不利用 OFF 进行跨调用合并或重排；这允许 ON 区域访问舍入模式和状态标志。pragma 本身不设置或恢复 MXCSR，程序须在进入 OFF 区域前满足默认控制模式等前提。静态常量求值使用默认最近偶数舍入，与运行时控制模式分开。此项仍不等于所有浮点库语义已穷尽验证。CX_LIMITED_RANGE 默认 OFF；所有状态均保留稳健的复数乘除实现，不利用 ON 放宽中间范围要求。cx-pragma、乘除范围和浮点环境测试检查上述策略；这一保守策略不构成完整满足可选 Annex F/G 的声明。FP_CONTRACT 的依据为 [N1256 6.5、7.12.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1256.pdf)。

## 字符分类与 locale

`components/wide-io/lib/ctype.c` 将大写、小写、数字分别限定为 ASCII 的 A..Z、a..z、0..9。isalpha 是前两者的并集，isalnum 再包含数字。控制字符为 0..31 与 127；可打印字符为 32..126，图形字符为 33..126，标点字符为图形字符中非字母数字者。空白包括空格及 `\t\n\v\f\r`。十六进制数字为 0..9、A..F、a..f。大小写转换仅改变上述 ASCII 字母，其余有效输入（包括 EOF）原样返回。128..255 不属于这些分类。

`components/wide-io/lib/locale.c` 仅提供 C locale。对有效类别，传入 `"C"` 或空字符串均选择 C，空指针查询返回 `"C"`；其他名称返回空指针。localeconv 的小数点为 `"."`，其余字符串字段为空，数值约定字段为 CHAR_MAX。C89 与 C99 头文件的字段命名差异由对应运行库包装处理。两种模式的布局和名称冲突检查由 locale 测试覆盖。

## 信号处理

`base/include/signal.h` 定义 sig_atomic_t 为 int，支持 SIGINT=2、SIGILL=4、SIGFPE=8、SIGSEGV=11、SIGTERM=15、SIGABRT=22。`components/wide-io/lib/signal.c` 初始处理方式均为 SIG_DFL。signal 返回此前处理器；无效编号或把 SIG_ERR 作为新处理器时返回 SIG_ERR 并设置 errno 为 EINVAL。

raise 在调用线程同步执行处理器。SIG_IGN 直接成功返回；调用自定义处理器前会将处置恢复为 SIG_DFL。默认处理立即终止进程，SIGABRT 的进程退出码为 3，其他支持信号为 128 加信号编号。abort 在 SIGABRT 被忽略或处理器返回后仍以状态 3 终止。当前信号模块使用内部处理器表；本文不承诺 Windows 控制台事件或硬件异常会转成这些 C 信号。

信号探针覆盖默认、忽略、处理器复位行为及 abort 场景；其结果不扩大为对操作系统异步事件、缓冲刷新和终止回调全部组合的保证。

## 文件流

以下规则依据 `components/wide-io/lib/stdio.c`、`stdio-temporary.c` 及公开 stdio 头文件。相关用例覆盖文本转换、追加与重开、缓冲读写位置、更新流及临时文件行为。

- 文本输出将每个 LF 写成 CR LF；文本输入将 CR LF 合成 LF，单独的 CR 保留。Ctrl-Z 没有特殊 EOF 含义。末尾不自动添加换行，换行前的空格不被删去。二进制模式不作这些转换，也不额外补零到记录边界。
- r、w、a 可以追加一个 `+` 和一个 `b`，二者顺序均可；不接受其他模式字符或重复修饰符。没有 b 时为文本模式。普通打开使用 Win32 共享读、写、删除权限，仍可能因文件系统或其他句柄的共享设置失败。
- w/w+ 在打开时创建或截断文件；普通更新写入只覆盖实际写到的字节，不截去其后的内容，文本换行转换不改变这一规则。关闭零长度普通文件不会自动删除它；之后可以重新打开并读到 EOF。同一文件可由多个 fopen 流同时打开，每个流有独立句柄、位置和缓存；可用流槽位、权限及其他句柄的共享设置仍可能限制打开。
- 文件名字节直接传给 CreateFileA，运行库不自行限制名字中的字符或改写路径。合法名字、设备名、大小写匹配及路径解析遵循 Windows 和目标文件系统；ANSI 代码页决定非 ASCII 字节的解释。FILENAME_MAX 是公开容量常量，不是对所有长度以内名字都能成功打开的保证。
- a 的初始文件位置在末尾；a+ 的初始读取位置在开头。追加模式每次底层写入前重新定位到末尾，fseek 不会使随后写入覆盖文件中间。本实现不保证多个并发写入者之间的“定位再写入”具有原子性。
- stdin/stdout 通过 GetConsoleMode 检测控制台：控制台使用行缓冲，否则使用全缓冲。stderr 初始无缓冲。普通 fopen 流初始全缓冲。BUFSIZ 为 4096；FOPEN_MAX 为 32，包含标准流槽位；FILENAME_MAX 与 L_tmpnam 为 260。
- ungetc 提供一个字节的回推槽。ftell 使用扣除未读缓存和回推、加上待写缓存后的物理字节位置；负值钳至零，超过 LONG_MAX 时失败并设置 ERANGE。fpos_t 内部保存 64 位位置。文本位置不能当作逻辑字符计数。
- rename 使用允许替换目标的 MoveFileExA；remove 区分普通文件和目录，分别调用 DeleteFileA 与 RemoveDirectoryA，目录必须满足系统删除条件。已打开文件的重命名或删除结果依赖 Win32 共享权限和文件系统。
- 临时文件位于 GetTempPathA 返回的目录，名字包含进程号、初始化时计时值和递增序号。创建使用 CREATE_NEW，碰撞时换名重试。tmpfile 以二进制更新模式打开，采用句柄关闭时删除；tmpnam 用短暂的新文件确认候选后关闭删除，并返回名字，因而不会为随后使用者保留该名字。

这些是当前平台的约定；不同文件系统、不可定位设备、异步进程终止和全部失败路径仍须结合对应测试进一步核验。FILE 和 fpos_t 的内部字段属于实现保留名字，应用不应直接依赖这些字段。

## 格式、诊断和异常终止的补充约定

以下约定适用于本发布版本。

- `fprintf` 系列的 `%p` 输出 `0x` 前缀和小写十六进制地址，默认不补足 16 位；空指针为 `0x0`。`fscanf` 系列按十六进制读取 `%p`，允许 `0x`/`0X` 前缀，至少需要一个数字；结果写入 `void **`。它能读取本实现输出的指针拼写。源码为 `runtime/lib/stdio-format.c`、`stdio-scan.c`，已有 format/scan 测试覆盖指针转换。
- `%[` 中首个 `]` 可作为集合成员；升序的 `a-z` 形式扩展为包含两端的字节范围。非升序连字符按普通成员处理，首尾连字符也按字面处理；`^` 选择字节集合的补集。该规则按字节值处理，不使用 locale 排序。
- 启用的 `assert` 向 stderr 输出 `Assertion failed: 表达式, file 文件, line 行号, function 函数名`，随后换行、刷新 stderr 并调用 abort。表达式文本来自字符串化，保留宏实参展开前的拼写。禁用时不求值参数。源码为 `base/include/assert.h`、`components/wide-io/lib/assert.c`；`base/checks/assert.ps1` 检查确切输出、缓冲刷新及单次求值。
- `strerror` 对 0、EDOM、ERANGE、EILSEQ、EINVAL 分别返回 `No error`、`Domain error`、`Range error`、`Illegal byte sequence`、`Invalid argument`，其他值返回 `Unknown error`。`perror` 先保存 errno，按需输出非空前缀和 `: `，再输出对应消息与换行，最后恢复 errno。它不直接返回 Windows 的系统错误文本。
- `fgetpos`、`ftell` 的无效流检查设置 errno 为 22；底层定位失败沿用统一 Win32 错误映射：文件/路径不存在为 2，拒绝访问及共享/锁冲突为 13，无效句柄为 9，内存不足为 12，无效参数为 22，磁盘满为 28，其他错误为 5。`ftell` 位置超出 LONG_MAX 另设置 ERANGE。源码为 `stdio.c` 的 `__c1_file_failure`、`__c1_file_position` 及两个公开函数。
- abort 最终经 `_Exit` 直接调用 ExitProcess，不执行 atexit 回调，也不主动刷新 C 流缓冲；SIGABRT 处理器自己完成的操作除外。退出时操作系统关闭句柄，tmpfile 的删除依靠创建时设置的关闭删除属性；普通文件中尚未写出的 C 缓冲不保证保存。这与正常 exit 的回调及流关闭路径不同。

这些条目补充 C89 实现定义行为文档要求；相关范围见 [C89 草案 A.6.3.13](https://www.columbia.edu/~ng2573/c89/c89-draft.html#A.6.3.13)。

## 整数库与随机数

`random.c` 初始状态为 1，srand 将状态设为传入的 unsigned int。rand 每次按 32 位无符号运算计算 `state = state * 1103515245U + 12345U`，返回状态右移 16 位后的低 15 位，范围为 0..32767。同一种子可重现序列；未调用 srand 时等同于种子 1。本实现不承诺随机序列具有密码学性质。

strtol/strtoul 使用 C locale 空白和 ASCII 数字、大小写字母，支持基数 2..36，基数零时按前缀选择。有效数字后仍继续扫描，即使已发现溢出，也将 endptr 移到整个有效数字串末尾；超界返回相应极值并设置 ERANGE。成功及无转换的路径不主动清零 errno。非法基数作为扩展处理：返回零、endptr 指回输入起点并设置 EINVAL。atoi/atol 走十进制转换路径。

不能给结果不可表示的 abs、除法或 atoi/atol 输入添加标准未要求的行为保证。

## 内存分配、入口与退出

`components/wide-io/lib/memory.c` 使用进程堆。malloc(0) 和乘积为零的 calloc 请求实际分配一个字节，成功时返回可传给 free 的非空指针，失败仍可返回空指针。calloc 先检查乘法溢出，溢出直接返回空指针；分配区由堆接口清零。realloc(NULL,n) 按 malloc(n) 处理，因此 realloc(NULL,0) 遵循 malloc(0) 的约定；对非空指针 realloc(p,0) 则释放 p 并返回空指针。free(NULL) 不作操作。内存分配包装不额外设置 errno。

公开构建入口 `compile-program.ps1` 的 `-MainArguments` 选择 main(int,char **) 的启动代码；未指定时选择 main(void)。`arguments.c` 读取 GetCommandLineA 的命令行并分配可修改的 argv 指针数组和字符串，argv[argc] 为空。程序名参数单独处理双引号，后续参数按空格/制表符、双引号与引号前反斜线规则拆分；相邻双引号及代码页前导字节亦有专门处理。不会自行展开通配符、读取响应文件或把参数改写为小写。字符串字节来自该 Win32 接口，不能据此承诺任意 Unicode 参数均无损。

`process.c` 支持 32 个尚未执行的 atexit 注册，按逆注册顺序调用；注册失败返回非零。正常 main 返回值送入 exit，先调用退出处理器，再关闭已初始化的流，最后把状态转换为 unsigned int 传给 ExitProcess。命令行准备失败的启动路径返回 127。abort 的路径另见信号处理一节。

memory-c89 测试覆盖零大小分配、calloc 溢出、扩缩容、失败保留、独立分配、NULL realloc 和对齐；另有命令行解析、程序入口及 C89/C99 驱动集成测试。极端资源耗尽、全部代码页及所有异常终止场景不在穷尽验证范围内。

## 时间和环境

`base/include/time.h` 将 time_t、clock_t 定义为有符号 64 位 long long，CLOCKS_PER_SEC 为 10000000。`time.c` 将 GetSystemTimeAsFileTime 的计数换算为从 1970-01-01 UTC 起的整秒；difftime 返回秒数差。gmtime 使用向过去延伸的公历规则，生成的秒字段为 0..59，不把闰秒作为额外秒表示。超出 tm_year 可表示范围时失败并设置 ERANGE。

`clock.c` 返回本进程内核态和用户态累计 CPU 时间之和，单位为 100 纳秒，既不是墙上时钟也不累计子进程时间。GetProcessTimes 失败时返回 `(clock_t)-1` 并设置 EINVAL，结果溢出有符号 64 位范围时设置 ERANGE。

`localtime.c` 与 `dynamic-zone.c` 使用 Windows 当前动态时区设置，并在可用时查询目标年份的规则。时区查询、年份范围或转换失败会返回失败值；因此不能从 time_t 的表示范围推断所有同范围年份都能转换为本地时间。localtime 与 gmtime 共用静态 struct tm 存储，后续调用会覆盖此前结果。asctime 使用另一块静态字符缓冲，ctime 调用 localtime 再调用 asctime。mktime 在 tm_isdst<0 时先按标准时偏移构造候选；若转换回墙上时间不匹配，再尝试夏令时偏移，仅当第二个候选精确匹配时采用它，否则保留第一个候选并写回正规化结果。常见的一小时回拨重叠因此选标准时，春季缺失时间向前正规化。对应行为由合成时区测试检查。tm_isdst>0 指定夏令时偏移，等于零指定标准时偏移，最终仍按时区规则写回结果。动态年份规则最多迭代四次以取得一致年份，失败返回 -1 并设置 ERANGE。此项不保证穷尽全部操作系统时区或时区在调用中变化的情况。

`environment.c` 通过 GetEnvironmentVariableA 查询变量，并返回运行库拥有的动态字符串。下一次成功查询会释放上一次成功查询的结果；调用者不得修改、释放或长期保留该指针。名称指向先前结果时，旧存储会保持到新查询完成。不存在、无效名称、查询或分配失败返回空指针。字符编码和名称匹配沿用该 Win32 接口，不保证全部非 ASCII 环境名称和值在不同代码页下的可移植性。

可查询的变量来自当前进程的 Windows 环境，通常由启动进程提供；本运行库不维护另一个固定名称清单。C89 库没有提供修改环境的函数；宿主或程序通过 Win32 接口修改当前进程环境后，后续 getenv 查询读取修改后的环境，而不是启动时的私有快照。

`system.c` 从 GetSystemDirectoryA 定位 cmd.exe，以 `/d /s /c` 执行命令并等待结束，不读取 COMSPEC 来选择解释器。空指针参数查询该路径是否存在且非目录。执行完成时返回子进程的退出码转换为 int 的值；准备、创建、等待或取退出码失败返回 -1。子进程使用当前环境、当前目录和标准句柄。源程序仍需按命令解释器的语法构造命令字符串。

时间、CPU 时钟和 system 测试覆盖时钟单位与溢出、命令退出码、引号、环境及标准输入输出；不穷尽所有时区和 Windows 环境配置。

## 日期时间宏与异常回退

编译器在首次展开 __DATE__ 或 __TIME__ 时读取本地日期时间，并在翻译单元内缓存。不可用或无法按所选格式表示的数据映射为 `Jan  1 1970`、`00:00:00`。有效年份范围为 1..9999，按公历检查月日、闰年和时钟字段；回调缓冲先清零。相关测试通过时钟桩检查正常、异常和缓存行为，不修改系统时钟。



## 语言模式与字符编码

以下约定汇集语言特性说明，适用于当前发布源码；功能存在不代表完整 C99 符合性。

### 通用字符名与函数名

C99 模式支持标识符、字符常量和字符串中的 UCN，C89 模式将其作为扩展诊断。标识符字符串化保留拼写；名称比较使用解码后的字符；符号表和自制目标文件采用规范 UTF-8，保留 63 个有效字符、最多 189 字节，链接器符号名上限为 255 字节。具体允许范围见 `bootstrap-c99/namespace/ucn/annex-d.txt`，依据为 N1256 6.4.2.1、6.4.3 和附录 D。

窄字面量使用单字节取值范围，宽字面量使用 16 位数值范围；合法 UCN 超出所选范围时映射为问号（63）。这不意味着任意 UTF-8 源文件或字符串会自动解码。标识符 UCN 在字符串化时不另加反斜杠，后续字面量解码会解释它。

`__func__` 使用定义处的完整函数名，解码 UCN 并转换到窄执行字符集，生成带零终止符的 const char 数组；不能表示的字符转为问号。其长度不受标识符比较时 63 个有效字符的截断影响。该数组的执行编码与目标文件中符号名的规范 UTF-8 编码相互独立。依据为 N1256 6.4.2.2。

本实现的 plain char 有符号，因此单个窄字符常量解码为 128–255 时，其 int 值为 -128–-1；只有恰好一个解码单元时进行这种符号扩展。多字符常量打包、宽字符值和字符串保存的字节不因此改变，依据为 C89 3.1.3.4 和 N1256 6.4.4.4。

### 初始化、常量表达式与 return

| 场景 | 行为 |
| --- | --- |
| C89 自动聚合/联合的初始化列表 | 使用常量表达式解析；自动标量初始化及不带花括号的记录复制初始化仍可使用一般表达式。C99 保留运行时聚合初始化 |
| C89 常量表达式中的逗号 | 对 C99 允许的未求值逗号表达式作扩展诊断；一般运行时逗号表达式及 sizeof 操作数按各自规则处理，不将逗号表达式误分类为 C89 整数常量表达式 |
| 非 void 函数中的裸 return | C89 模式允许；测试调用者丢弃返回值，只检查副作用和提前退出。C99 模式发出约束诊断；这不赋予未提供的返回值以确定含义 |
| void 函数返回表达式 | 两种模式均不允许 |

依据包括 [C90 issue 150](https://www.open-std.org/jtc1/sc22/wg14/issues/c90/issue0150.html)、C89 3.4、C99 6.6、[N1448](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1448.htm) 和 [N739](https://open-std.org/jtc1/sc22/wg14/www/docs/n739.htm)。N1448 的提案不被当作已经采纳的 C99 勘误。

### 预处理约束与变长数组

活动预处理指令的记号之间出现垂直制表符或换页符时发出诊断；指令之前的空白、普通源码空白、注释、字面量及被包含文件内容按各自规则处理。

预处理后的翻译单元必须包含外部声明；C89/C99 模式都在目标文件输出前诊断空记号流。仅有 typedef、前向标签、函数原型或 extern 对象声明的翻译单元仍然有效。依据为 C89 3.7/2.1.1.3 和 N1256 6.9/5.1.1.3。

C99 变长数组支持原型和运行时边界、自动数组存储、保存后的 sizeof/步长、函数参数求值、作用域清理以及变长修改类型声明的约束。对应测试和审计位于 `bootstrap-c99/namespace/test-vla.ps1` 与 `audit-vla.ps1`。这些能力不扩大其他章节列出的限制。
